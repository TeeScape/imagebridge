## What you get

| | runs on | needs a key | use for |
|---|---|---|---|
| `/imagebridge:draw` | Codex `$imagegen` (gpt-image-2 class) | **no** | icons, illustrations, mockups, placeholder art |
| `/imagebridge:ask` | `codex exec` | **no** | second opinion on a diff, delegated coding tasks, reading screenshots |
| `/imagebridge:exact` | `openai images generate` | yes | images needing an exact size, quality or count |
| `/imagebridge:edit` | Codex `$imagegen` + `referenced_image_paths` | **no** | changing part of an image and keeping the rest |
| `/imagebridge:remove` | your own inpainting endpoint | **no** (self-hosted) | deleting an object and filling the gap |
| `/imagebridge:inspect` | pure arithmetic, locally | **no** | checking an edit did what was asked |
| `/imagebridge:doctor` | — | — | check your setup |

Plus a **skill** that fires on its own: say *"make me an icon for this"* or *"ask Codex what it thinks
of this diff"* and Claude reaches for the right one without you typing a command.

### MCP tools

The plugin also ships an **MCP server**, so Claude gets real typed tools instead of shelling out:

| tool | does |
|---|---|
| `generate_image` | prompt, optional `output_path` / `output_dir` / `reference_images` / `transparent` / `return_image` / `max_dimension` → returns the saved path |
| `edit_image` | prompt, `images[]`, optional `from_last`; `provider` defaults to the **free** Codex path → returns the edited path |
| `ask_codex` | prompt, optional `cwd` / `allow_writes` / `images` / `stdin_text` → returns Codex's answer |
| `remove_object` | `image`, and **either** `regions` (`[x, y, w, h]` boxes) **or** a `mask` PNG where alpha 0 is the hole → returns the filled path. Off until you configure an endpoint |
| `inspect_image` | `image`, optional `compare_to` / `tolerance` → size, transparency, dominant colours, and for a pair: pixels changed, the box they landed in, silhouette IoU |
| `check_setup` | reports what is installed, signed in and missing |

It is **one Python file with no dependencies** — stdlib only, nothing to `pip install`. It needs
`python3` on your PATH; without it the MCP tools simply don't appear and everything else still works.

`generate_image` runs for 45–60 s. If your client gives up first, raise its MCP tool timeout:

```bash
export MCP_TOOL_TIMEOUT=600000   # milliseconds
```

## Requirements

- [Claude Code](https://claude.com/claude-code)
- [OpenAI Codex CLI](https://github.com/openai/codex), signed in with ChatGPT:
  ```bash
  brew install --cask codex    # or: npm install -g @openai/codex
  codex login
  ```
- *Optional*, only for `openai-image`: `brew install openai/tools/openai` and an `OPENAI_API_KEY`.

A paid ChatGPT plan (Plus/Pro/Business) is what makes the no-API-key path work — image generation
spends that plan's quota.

## Use

Let the skill pick it up:

> make a flat vector icon of a blue folder and put it in `assets/`

Or drive it directly:

```
/imagebridge:draw a tiny orange robot watering a houseplant -o out/robot.png
/imagebridge:ask review the staged diff for off-by-one errors
/imagebridge:exact a blue folder icon --size 1024x1024 --background transparent
```

The scripts also stand alone:

```bash
IMG=$(codex-image "flat vector icon of a blue folder" -o assets/folder.png)
codex-ask -C ~/code/myapp "explain what src/auth.ts does"
git diff | codex-ask --stdin "review this diff for bugs"
codex-ask --schema schema.json -C . "extract the dependency list"
```

Every command prints its result on stdout and nothing else, so it composes: `codex-image` prints the
saved file's absolute path, `codex-ask` prints Codex's final message. `-h` gives the full flag list.

## What to expect

- `codex-ask`, simple round trip: **~8 s**, ~3k tokens.
- `codex-image`: **~45–60 s**, ~10–12k tokens per image.
- **You cannot set the image size on the Codex path.** This is not a missing flag: Codex's image
  tool takes exactly five arguments — `prompt`, `gif`, `transparent_background`,
  `referenced_image_paths`, `num_last_images_to_include` — and none of them is a size. Wording
  *steers* it (across 146 generations, every prompt containing "icon" or "square" came back 1:1,
  while unqualified ones came back 3:2), but nothing guarantees it. Use `/imagebridge:exact` when
  a size is a requirement rather than a preference.
- **Transparency, however, is available for free.** `transparent_background` is one of those five
  arguments, so `-t/--transparent` works on the Codex path without an API key.

## Why the scripts exist instead of calling `codex` directly

Four traps, all hit while building this:

1. **`codex exec` hangs forever under an agent.** It reads stdin whenever stdin is not a TTY and waits
   for EOF — and an agent's pipe never closes. The scripts detach stdin unless you pass `--stdin`.
2. **`-i/--image` is variadic** and swallows the prompt as another filename. The scripts put image
   flags last and insert `--` before the prompt.
3. **The model will not respect an output path.** Told to save `out/folder-icon.png`, it wrote
   `blue-folder.png` in the repo root instead. `codex-image` therefore ignores what the model says and
   copies the file out of Codex's own `~/.codex/generated_images/<session>/` into a path it controls.
4. **A local `~/.codex/config.toml` can hijack the call.** Pointing `openai_base_url` at Ollama or
   another local provider silently routes these calls away from OpenAI. The scripts pass
   `--ignore-user-config`; `--user-config` opts back in.

Also: `codex` refuses to run outside a git repo without `--skip-git-repo-check` (always passed), and
`--full-auto` has been removed from Codex — `-w` maps to `--sandbox workspace-write`.

## Safety

`codex-ask` runs **read-only** by default: Codex may read files and run commands, but not write.
`-w` allows writes inside the working root. `--yolo` removes the sandbox entirely and exists only for
environments that are already isolated.

The plugin never handles your credentials. `codex login` is yours to run, and `openai-image` refuses
to go hunting for an API key — it reads `OPENAI_API_KEY` from the environment or from a `.env` you
place next to the plugin, and otherwise just tells you it is unset.

## Design decisions

**No plugin-root `bin/`.** Claude Code can put a plugin's `bin/` directory on the Bash tool's
PATH, which would let the skill call `codex-image` as a bare command instead of
`bash "<resolved path>"`. This plugin deliberately does not use it:

- It would only simplify the *last* fallback. The primary path is the MCP tools, and the slash
  commands already resolve scripts through `${CLAUDE_PLUGIN_ROOT}`. Both work today.
- It would put three generically-named executables — `codex-ask`, `codex-image`, `openai-image` —
  on the PATH of every shell command in every session where the plugin is enabled. That is a
  surprising side effect for an image plugin, and an easy way to collide with something else.
- The plugin reference states that claude.ai and Cowork will not install a plugin containing this
  directory. *(Taken from the docs; not independently reproduced here.)*
- Of the 60 installed plugins checked locally — Anthropic's own marketplace included — none ships
  a plugin-root `bin/`. Anthropic's examples put scripts in `bin/` but still invoke them by
  explicit `${CLAUDE_PLUGIN_ROOT}/bin/...` path, never as bare commands.

If you want the commands on your PATH anyway, `./install.sh` symlinks them into `~/bin`, which
keeps that choice with the user instead of baking it into the plugin.

## Seeing the result, and sizing it

`return_image: true` returns a 384 px preview as an inline image, so the model can look at what
it just made instead of being told a path and taking it on faith. `max_dimension: 512` shrinks
the saved file afterwards — the generated size is still the model's choice, but the file you keep
is the size you asked for.

```
Generated 1 image:
  assets/apple.png  (512x512, 183737 bytes)
- resized apple.png from 1254x1254 to 512x512
- preview of apple.png shown at 384x384
```

Both work with **no dependencies**. `mcp/imagelib.py` decodes, resamples and re-encodes PNG with
nothing but `zlib` and `struct`; the bilinear resampler is a port of the one in the
[analogue](https://teerapol-k.com/) photo editor, which is plain arithmetic with no imaging
library behind it. Scope is deliberate — 8-bit, non-interlaced, colour types 0/2/4/6, which is
what the image models emit. Anything else skips the preview instead of failing the generation.

A preview costs about 3 seconds on a 1.2 MP image, against the 45–60 the generation itself takes.

## Editing is free

Codex edits images on your ChatGPT plan. Its own tool documentation says so — *"For edits, use
`referenced_image_paths` when every target image has a local file path"* — and `codex-image -r`
drives exactly that:

```bash
codex-image "change the folder to green, nothing else" -r assets/folder.png -o assets/folder.png
```

Measured, not assumed. Editing a 1254×1254 icon from blue to orange:

| | source | result |
|---|---|---|
| dimensions | 1254×1254 | 1254×1254 |
| silhouette overlap (IoU) | — | **1.000** |
| average ink colour | `(1, 100, 243)` | `(245, 120, 19)` |

The shape is preserved pixel for pixel; only the colour changed. `--from-last N` edits the last
N images of the Codex conversation when they have no file on disk.

### The two things the free path genuinely cannot do

| | why | where |
|---|---|---|
| an exact output size | Codex's image tool has no size argument | `/imagebridge:exact` |
| a pixel mask | no mask argument either | `edit_image` with `provider: "api"` |

Both bill the OpenAI API per call and need `OPENAI_API_KEY`. Everything else — editing,
transparency, references, GIFs — is free.

On the paid path the mask rule is the opposite of most people's instinct: the **fully
transparent** areas are the ones that get **edited**, and the mask must be a PNG with an alpha
channel and exactly the image's dimensions. `openai-edit` checks all of that locally and refuses
before spending anything:

```
openai-edit: the mask must have the same dimensions as the image.
             image src.png: 64x64
             mask  mask.png: 96x96
```

## Measuring the result instead of trusting it

Every image tool here ends by returning a path and an agreeable sentence. Neither is evidence.
`inspect_image` measures:

```
apple-noleaf.png: 512x512, no alpha
  mean #f8a6a4, mostly #f8f8f8 (65%), #f80808 (34%)
Against apple-512.png: 3.1% of pixels changed, all inside [x=265 y=50 w=123 h=100].
  silhouette IoU 1.000 - the visible shape is unchanged
```

That box is the whole point: "change only the sky" becomes checkable rather than believable, and
`changed_pixels: 0` catches the case where nothing happened at all — which otherwise reads
exactly like success. The README's own 1.000 IoU figure further up was measured this way.

It is free, offline and instant, so use it after every edit. `tolerance` defaults to 8 so PNG
re-encoding noise is not reported as an edit.

## Object removal (optional)

`remove_object` erases something from a photo and fills the hole plausibly. It is the one tool
here that does **not** run on the ChatGPT plan: it posts a 512×512 RGBA PNG to an inpainting
endpoint and gets one back. ImageBridge deliberately ships **no default URL** — whose machine
does that work is your choice, not ours — so the tool refuses until you point it somewhere:

```bash
export IMAGEBRIDGE_INPAINT_URL=https://inpaint.example.com/api/inpaint
```

or, so it persists:

```json
// ~/.imagebridge/config.json
{ "inpaint_url": "https://inpaint.example.com/api/inpaint" }
```

The contract is one POST, body `image/png`, response `image/png`: a 512×512 RGBA image in which
**alpha 0 marks the hole**, answered with the filled RGB image. Any LaMa (Apache-2.0) or MI-GAN
(MIT) server with that shape works; nothing proprietary is involved.

Two honest limits:

- **It removes; it does not invent.** "Delete the person on the left" is what this is for.
  "Give him a hat" is not — that is `/imagebridge:edit`.
- **The box must cover the whole object.** Clip an edge and you get a visible stub of it back.
  This is the usual cause of a disappointing result, not the model.

Everything outside the mask is left bit-for-bit alone: the fill is composed back through the
mask, not pasted over the picture.

## Tests

```bash
./tests/run.sh
```

74 checks against a **stub codex** and a **stub `openai` CLI**, so the suite costs nothing, needs no network and no ChatGPT
quota. Every check exists because a real bug got past its absence: a failed generation reported as
a success, `-o` quietly forking into `-2`, `-3`, a Thai description collapsing to a generic
filename, a JSON-RPC array killing the server.

The edit path is covered by a stub too, so the mask rules are tested without a paid call. The
live API call itself is the one thing the suite cannot exercise — see the note in `edit.md`.

CI runs it on **ubuntu-latest as well as macos-latest**, which is not optional: three of the bugs
it guards against are GNU-vs-BSD differences that a macOS-only run cannot see.
